# v4.3 复杂任务书模板

> 本任务书是当前已批准需求和方案的执行投影，不是唯一裁决入口，也不增加一次用户批准。字段必须从有效 `CURRENT.md` 和已批准方案复制；approval_cycle 不得自行重算。

```markdown

base_ref: <不可移动、内容寻址、可重建>
candidate_ref: null
base_role: <subagent_executor | subagent_executor_flash>
required_skill: <role-frontend | role-data-analyst | role-doc-writer | none>
executor_model: <实际路由>
reviewer_route: <已批准的 reviewer 实例>
verification_mode: independent
capability_scope:
  read: []

  tools: []

## 范围与红线

### 可写

- {path}

### 只读

- {path}

### 禁止

- 不修改 `CURRENT.md`、`BLOCKED.md`、本任务书、批准记录和既有证据。
- 不扩大 capability_scope，不 merge/push，不执行未批准的外部写入或不可逆动作。
- 不跳过测试、放宽断言、替换真实被测对象或伪造通过。

## 开工自检

1. 读取本任务书、项目 `AGENTS.md` 和必要规格。
2. 核对任务与 CURRENT 的 task/revision/cycle 完全一致。
3. 核对 base_ref 可重建、required Skill 可加载、模型与能力真实可用；核对 permission_scope 已填且 ⊆ capability_scope。
4. 实质不一致时停止并返回 Planner；普通实现细节在范围内自主决定。
5. 现场遇到 permission_scope 未列入的资源需求（工作区外写入、网络端口、守护进程、付费、不可逆操作）时，不请求权限、不做降级替代，立即停止并返回 Planner 回停点二补版。

## 停机与 BLOCKED

- wall-clock 不能通过换 Agent、换 session 或重写任务书静默重置。
- 同一路线同根因最多两次，不以改名重置。
- 新路线、模型、外部影响、风险或不可逆性变化回停点二；需求/验收变化回停点一。
- 缺必要信息/权限/业务裁决或约束矛盾且无独立路径时 BLOCKED；局部受阻不妨碍独立路径继续。

## 证据与交付

- 执行报告：`docs/phase_reports/{task_id}_{cycle_hash}_{branch_id}_e{execution_round}_report.md`
- 原始验证：`docs/phase_reports/{task_id}_{cycle_hash}_{branch_id}_e{execution_round}_verify.log`
- `cycle_hash` 直接取 approval_cycle 去掉 `ac1:` 后的完整 64 位值，不重新计算；跨 cycle 不复用文件名。
- 报告记录实际实例、模型、Skill、改动与未跟踪文件、命令、cwd、工具版本、退出码、原始输出、偏离和回滚。
- Executor 只提交候选与待核实证据，不判 PASS；Planner 冻结 candidate_ref 后由带新 subagentId 的 Fresh Reviewer 审查。
- 跨 session 仅写 `handoffs/` 交接，不创建 `PROGRESS.md` 平行状态。
```
